Machine Learning과 Deep Learning에서 Classification Model을 학습한 후에는 모델이 얼마나 정확하게 분류하는지 평가해야 한다.

이때 사용하는 지표를 **Evaluation Metrics(성능평가지표)** 라고 한다.

Classification에서 가장 핵심적인 성능지표는 다음 네 가지이다.

| Metric | 한국어 | 핵심 의미 |
| --- | --- | --- |
| **Accuracy** | 정확도 | 전체 예측 중 얼마나 맞혔는가? |
| **Precision** | 정밀도 | Positive라고 예측한 것 중 실제 Positive는 얼마나 되는가? |
| **Recall** | 재현율 | 실제 Positive 중 모델이 얼마나 찾아냈는가? |
| **F-score** | F-점수 | Precision과 Recall을 얼마나 균형 있게 달성했는가? |

이 네 가지 지표는 모두 **Confusion Matrix(혼동행렬)** 를 기반으로 이해할 수 있다.

특히 Accuracy가 높다고 해서 반드시 좋은 Classification Model이라고 판단할 수는 없다.

데이터의 Class Distribution이 불균형한 경우에는 Accuracy보다 Precision, Recall, F-score가 더 중요한 정보를 제공할 수 있기 때문이다.

이 글에서는 Binary Classification을 기준으로 Confusion Matrix의 개념을 살펴보고, 네 가지 성능지표의 정의와 수식, 실제 계산 예제 및 Python 구현 방법을 정리한다.

# 1. Classification Model의 성능평가

Classification은 입력 데이터를 사전에 정의된 Class 중 하나로 분류하는 Task이다.

예를 들어 의료 데이터를 이용하여 이상 여부를 분류한다고 하자.

```text
Input Data
    │
    ▼
Classification Model
    │
    ▼
Prediction
    │
    ├── Normal (0)
    │
    └── Abnormal (1)
```

여기서

- `0`: Negative Class
- `1`: Positive Class

로 정의한다.

모델이 출력한 Prediction과 실제 Label(Ground Truth)을 비교하면 모델의 성능을 평가할 수 있다.

예를 들어 다음과 같다.

| Sample | Actual Label | Prediction | 결과 |
| --- | --- | --- | --- |
| 1 | 1 | 1 | 정답 |
| 2 | 0 | 0 | 정답 |
| 3 | 1 | 0 | 오답 |
| 4 | 0 | 1 | 오답 |
| 5 | 1 | 1 | 정답 |

이러한 예측 결과를 체계적으로 정리한 것이 Confusion Matrix이다.

---

# 2. Confusion Matrix(혼동행렬)

Confusion Matrix는 Classification Model의 예측 결과와 실제 Label을 비교하여 나타낸 행렬이다.

Binary Classification에서는 다음 네 가지 경우가 존재한다.

- True Positive (TP)
- True Negative (TN)
- False Positive (FP)
- False Negative (FN)

여기서 Positive는 관심 있는 Class를 의미한다.

예를 들어 이상 탐지 모델에서는 일반적으로 이상 상태를 Positive로 정의할 수 있다.

---

## 2.1 Confusion Matrix의 구조

Binary Classification의 Confusion Matrix는 다음과 같다.

| Actual \ Predicted | Negative (0) | Positive (1) |
| --- | --- | --- |
| **Negative (0)** | TN | FP |
| **Positive (1)** | FN | TP |

여기서 중요한 점은 다음과 같다.

- **Row(행):** Actual Label
- **Column(열):** Predicted Label

즉 행은 실제 정답을 나타내고, 열은 모델의 예측 결과를 나타낸다.

---

## 2.2 True Positive (TP)

**실제로 Positive인 데이터를 Positive라고 올바르게 예측한 경우**이다.

```text
Actual     : Positive
Prediction : Positive
Result     : Correct
```

예를 들어 실제 이상 상태인 데이터를 모델이 이상 상태라고 판정한 경우이다.

$$
\boxed{TP=\text{True Positive}}
$$

---

## 2.3 True Negative (TN)

**실제로 Negative인 데이터를 Negative라고 올바르게 예측한 경우**이다.

```text
Actual     : Negative
Prediction : Negative
Result     : Correct
```

예를 들어 실제 정상 상태인 데이터를 모델이 정상이라고 판정한 경우이다.

$$
\boxed{TN=\text{True Negative}}
$$

---

## 2.4 False Positive (FP)

**실제로 Negative인데 Positive라고 잘못 예측한 경우**이다.

```text
Actual     : Negative
Prediction : Positive
Result     : Incorrect
```

예를 들어 정상 상태를 이상 상태라고 잘못 판단한 경우이다.

이를 **False Alarm(오경보)** 과 연결하여 이해할 수 있다.

$$
\boxed{FP=\text{False Positive}}
$$

통계적 가설검정에서는 특정 조건에서 Type I Error와 연결된다.

---

## 2.5 False Negative (FN)

**실제로 Positive인데 Negative라고 잘못 예측한 경우**이다.

```text
Actual     : Positive
Prediction : Negative
Result     : Incorrect
```

예를 들어 실제 이상 상태를 정상이라고 잘못 판단한 경우이다.

이를 **Missed Detection(미탐지)** 과 연결하여 이해할 수 있다.

$$
\boxed{FN=\text{False Negative}}
$$

통계적 가설검정에서는 특정 조건에서 Type II Error와 연결된다.

---

## 2.6 Confusion Matrix 핵심 정리

| 구분 | Actual | Prediction | 의미 |
| --- | --- | --- | --- |
| TP | Positive | Positive | Positive를 올바르게 탐지 |
| TN | Negative | Negative | Negative를 올바르게 분류 |
| FP | Negative | Positive | 잘못된 Positive 판정 |
| FN | Positive | Negative | Positive를 탐지하지 못함 |

여기서 기억해야 할 것은 다음과 같다.

> **True / False는 예측이 맞았는지를 나타내고, Positive / Negative는 모델이 어떤 Class로 예측했는지를 나타낸다.**

따라서

```text
TP, TN → Correct Prediction

FP, FN → Incorrect Prediction
```

이다.

---

# 3. 성능평가를 위한 예제

이제 하나의 Confusion Matrix를 이용해 네 가지 성능지표를 모두 계산해 보자.

총 100개의 데이터를 분류한 모델이 있다고 가정하자.

실제 Label과 Prediction을 비교한 결과는 다음과 같다.

| Actual \ Predicted | Negative | Positive | 합계 |
| --- | --- | --- | --- |
| **Negative** | 50 (TN) | 10 (FP) | 60 |
| **Positive** | 20 (FN) | 20 (TP) | 40 |
| **합계** | 70 | 30 | 100 |

따라서

$$
\boxed{ TP=20,\quad TN=50,\quad FP=10,\quad FN=20 }
$$

이다.

전체 Sample 수는 다음과 같다.

$$
\boxed{ N=TP+TN+FP+FN=100 }
$$

이 데이터를 기준으로 각 지표를 계산해 보자.

---

# 4. Accuracy(정확도)

Accuracy는 **전체 Sample 중 모델이 올바르게 예측한 Sample의 비율**이다.

즉 가장 직관적인 Classification 성능지표이다.

## 4.1 수식

$$
\boxed{ \operatorname{Accuracy} = \frac{\text{Correct Predictions}}{\text{Total Samples}} }
$$

Binary Classification에서는 올바른 예측이 TP와 TN이다.

따라서

$$
\boxed{ \operatorname{Accuracy} = \frac{TP+TN}{TP+TN+FP+FN} }
$$

이다.

---

## 4.2 계산 예제

앞에서 정의한 Confusion Matrix를 이용하자.

$$
TP=20,\quad TN=50,\quad FP=10,\quad FN=20
$$

Accuracy는 다음과 같다.

$$
\operatorname{Accuracy} = \frac{20+50}{20+50+10+20}
$$

따라서

$$
\boxed{ \operatorname{Accuracy}=0.7=70\% }
$$

이다.

즉 **100개의 데이터 중 70개를 올바르게 분류했다**는 의미이다.

---

## 4.3 Accuracy의 한계

Accuracy는 이해하기 쉽지만 Class Imbalance(클래스 불균형)가 존재하는 경우에는 성능을 제대로 나타내지 못할 수 있다.

예를 들어 1,000개의 데이터가 있다고 하자.

- Negative: 999개
- Positive: 1개

이때 모델이 모든 데이터를 Negative로 예측한다고 가정하자.

```text
Total Samples : 1000

Actual Positive : 1
Actual Negative : 999

Model Prediction:
모든 데이터를 Negative로 예측
```

이 경우 Confusion Matrix는 다음과 같다.

| Actual \ Predicted | Negative | Positive |
| --- | --- | --- |
| Negative | 999 | 0 |
| Positive | 1 | 0 |

따라서

$$
TP=0,\quad TN=999,\quad FP=0,\quad FN=1
$$

이다.

Accuracy는 다음과 같다.

$$
\operatorname{Accuracy} = \frac{0+999}{1000}
$$

따라서

$$
\boxed{ \operatorname{Accuracy}=99.9\% }
$$

이다.

하지만 실제 Positive를 단 한 개도 찾아내지 못했다.

즉 **Accuracy는 99.9%이지만 Positive Detection 성능은 매우 나쁜 모델**이다.

이러한 이유로 Imbalanced Dataset에서는 Precision과 Recall을 함께 확인하는 것이 중요하다.

---

# 5. Precision(정밀도)

Precision은 **모델이 Positive라고 예측한 Sample 중 실제로 Positive인 Sample의 비율**이다.

즉 다음 질문에 답하는 지표이다.

> 모델이 Positive라고 판단한 결과를 얼마나 신뢰할 수 있는가?

---

## 5.1 수식

$$
\boxed{ \operatorname{Precision} = \frac{TP}{TP+FP} }
$$

여기서

- $TP$: Positive라고 올바르게 예측한 수
- $FP$: Positive라고 잘못 예측한 수

이다.

분모에 주목하자.

$$
TP+FP
$$

는 **모델이 Positive라고 예측한 전체 Sample 수**이다.

따라서 Precision은 모델의 Positive Prediction을 기준으로 계산한다.

```text
Predicted Positive
        │
        ├── TP : Correct
        │
        └── FP : Incorrect
```

즉

$$
\boxed{ \text{Precision} = \frac{\text{올바른 Positive 예측}} {\text{모든 Positive 예측}} }
$$

이다.

---

## 5.2 계산 예제

앞에서 정의한 Confusion Matrix는 다음과 같다.

$$
TP=20,\quad FP=10
$$

따라서

$$
\operatorname{Precision} = \frac{20}{20+10}
$$

이다.

계산하면

$$
\boxed{ \operatorname{Precision} \approx0.667=66.7\% }
$$

이다.

즉 모델이 Positive라고 예측한 30개 중 실제로 Positive인 데이터는 20개라는 의미이다.

---

## 5.3 Precision이 중요한 상황

Precision은 **False Positive를 줄이는 것이 중요한 상황**에서 특히 유용하다.

예를 들어 정상 데이터를 이상 데이터로 잘못 분류하면 불필요한 후속 조치가 발생하는 시스템을 생각해 보자.

이 경우 FP가 증가하면 Precision이 감소한다.

$$
\operatorname{Precision} = \frac{TP}{TP+FP}
$$

따라서 Precision을 높이려면 Positive라고 잘못 예측하는 사례를 줄여야 한다.

정리하면 다음과 같다.

> **Precision은 Positive라고 예측한 결과의 신뢰성을 평가하는 지표이다.**

---

# 6. Recall(재현율)

Recall은 **실제로 Positive인 Sample 중 모델이 Positive라고 올바르게 찾아낸 Sample의 비율**이다.

다음 질문에 답하는 지표이다.

> 실제로 존재하는 Positive 데이터를 모델이 얼마나 놓치지 않고 찾아냈는가?

Recall은 다음 이름으로도 불린다.

- Sensitivity(민감도)
- True Positive Rate(TPR)

---

## 6.1 수식

$$
\boxed{ \operatorname{Recall} = \frac{TP}{TP+FN} }
$$

여기서

- $TP$: Positive를 올바르게 탐지한 수
- $FN$: Positive를 탐지하지 못한 수

이다.

분모에 주목하자.

$$
TP+FN
$$

는 **실제로 Positive인 전체 Sample 수**이다.

따라서 Recall은 실제 Positive 데이터를 기준으로 계산한다.

```text
Actual Positive
       │
       ├── TP : Detected
       │
       └── FN : Missed
```

즉

$$
\boxed{ \text{Recall} = \frac{\text{찾아낸 Positive}} {\text{실제 모든 Positive}} }
$$

이다.

---

## 6.2 계산 예제

앞에서 정의한 Confusion Matrix는 다음과 같다.

$$
TP=20,\quad FN=20
$$

따라서

$$
\operatorname{Recall} = \frac{20}{20+20}
$$

이다.

계산하면

$$
\boxed{ \operatorname{Recall}=0.5=50\% }
$$

이다.

즉 실제로 Positive인 데이터가 40개 존재하지만, 모델은 그중 20개만 찾아냈다는 의미이다.

나머지 20개는 Negative라고 잘못 판정하였다.

---

## 6.3 Recall이 중요한 상황

Recall은 **False Negative를 줄이는 것이 중요한 상황**에서 특히 유용하다.

예를 들어 이상 상태를 놓치면 문제가 발생할 수 있는 탐지 시스템을 생각해 보자.

이 경우 실제 Positive를 Negative라고 판단하는 FN이 중요하다.

Recall은 다음과 같다.

$$
\operatorname{Recall} = \frac{TP}{TP+FN}
$$

따라서 FN이 증가하면 Recall이 감소한다.

반대로 실제 Positive를 최대한 많이 탐지하면 Recall이 증가한다.

정리하면 다음과 같다.

> **Recall은 실제 Positive를 얼마나 빠짐없이 찾아냈는지 평가하는 지표이다.**

---

# 7. Precision과 Recall의 차이

Precision과 Recall은 모두 Positive Class에 대한 성능을 평가한다.

하지만 **분모가 다르다**는 점이 핵심이다.

### Precision

$$
\boxed{ \operatorname{Precision} = \frac{TP}{TP+FP} }
$$

모델이 Positive라고 예측한 Sample을 기준으로 계산한다.

### Recall

$$
\boxed{ \operatorname{Recall} = \frac{TP}{TP+FN} }
$$

실제로 Positive인 Sample을 기준으로 계산한다.

두 지표를 비교하면 다음과 같다.

| 구분 | Precision | Recall |
| --- | --- | --- |
| 한국어 | 정밀도 | 재현율 |
| 기준 | Predicted Positive | Actual Positive |
| 계산식 | $TP/(TP+FP)$ | $TP/(TP+FN)$ |
| 주요 관심 | 예측한 Positive의 신뢰성 | 실제 Positive의 탐지율 |
| 관련 오류 | False Positive | False Negative |
| 대표 질문 | Positive라고 예측한 것이 얼마나 맞는가? | 실제 Positive를 얼마나 찾아냈는가? |

가장 중요한 차이는 다음과 같다.

```text
Precision
    │
    ▼
Predicted Positive 기준
    │
    ▼
FP에 주목


Recall
    │
    ▼
Actual Positive 기준
    │
    ▼
FN에 주목
```

즉 **Precision은 예측 결과의 신뢰성**, **Recall은 실제 대상의 탐지율**에 초점을 둔다.

---

# 8. Precision–Recall Trade-off

Precision과 Recall은 Classification Threshold에 따라 서로 다른 방향으로 변화할 수 있다.

Binary Classification에서는 모델이 Positive Class의 확률을 출력한다고 하자.

예를 들어 다음과 같다.

$$
P(Y=1\mid x)=0.8
$$

이 확률을 실제 Label로 변환하려면 Threshold가 필요하다.

일반적으로 다음과 같이 설정할 수 있다.

$$
\boxed{ \hat{y}= \begin{cases} 1,&P(Y=1\mid x)\ge t\\ 0,&P(Y=1\mid x)<t \end{cases} }
$$

여기서 $t$는 Classification Threshold이다.

---

## 8.1 Threshold를 높이는 경우

예를 들어 Threshold를 다음과 같이 변경한다고 하자.

$$
t=0.5\rightarrow0.9
$$

모델은 매우 높은 Positive Probability를 가진 Sample만 Positive로 분류하게 된다.

따라서 Positive로 예측하는 Sample의 수가 감소하거나 유지된다.

일반적으로 다음 경향이 나타날 수 있다.

- False Positive 감소
- Precision 향상 가능
- False Negative 증가 가능
- Recall 감소 가능

다만 Threshold를 높인다고 Precision이 반드시 증가하는 것은 아니다.

실제 변화는 모델이 출력한 Score의 분포에 따라 달라진다.

---

## 8.2 Threshold를 낮추는 경우

반대로 Threshold를 낮춘다고 하자.

$$
t=0.9\rightarrow0.3
$$

이 경우 더 많은 Sample이 Positive로 분류된다.

일반적으로 다음 경향이 나타날 수 있다.

- True Positive 증가 또는 유지
- Recall 증가 또는 유지
- False Positive 증가 가능
- Precision 감소 가능

따라서 Precision과 Recall 사이에는 Trade-off가 존재할 수 있다.

```text
Threshold 증가
        │
        ▼
Positive 판정이 엄격해짐
        │
        ├── FP 감소 가능
        │
        └── FN 증가 가능


Threshold 감소
        │
        ▼
Positive 판정이 관대해짐
        │
        ├── TP 증가 가능
        │
        └── FP 증가 가능
```

중요한 것은 어떤 지표가 무조건 높은 것이 아니라 **모델이 사용되는 목적에 적합한 Threshold를 설정하는 것**이다.

# 9. F-score

F-score는 **Precision과 Recall을 함께 반영하는 성능지표**이다.

Precision만 높거나 Recall만 높은 모델보다 두 지표가 균형 있게 높은 모델을 평가하는 데 사용한다.

대표적으로 F1-score가 널리 사용된다.

---

## 9.1 F1-score

F1-score는 Precision과 Recall의 Harmonic Mean(조화평균)이다.

수식은 다음과 같다.

$$
\boxed{ F_1 = 2\frac{ \operatorname{Precision}\times\operatorname{Recall} }{ \operatorname{Precision}+\operatorname{Recall} } }
$$

조화평균은 두 값 중 하나가 지나치게 작으면 결과도 낮아지는 특성이 있다.

즉 Precision과 Recall 중 한쪽만 높은 모델에 높은 점수를 부여하지 않는다.

---

## 9.2 F1-score 계산 예제

앞에서 계산한 결과는 다음과 같다.

$$
\operatorname{Precision} = \frac23
$$

$$
\operatorname{Recall} = \frac12
$$

이다.

따라서 F1-score는 다음과 같다.

$$
F_1 = 2\frac{ \frac23\times\frac12 }{ \frac23+\frac12 }
$$

이를 정리하면

$$
F_1 = \frac{2/3}{7/6}
$$

이므로

$$
\boxed{ F_1=\frac47\approx0.5714 }
$$

이다.

따라서

$$
\boxed{ F_1\approx57.1\% }
$$

이다.

---

## 9.3 F1-score의 다른 표현

Precision과 Recall을 이용한 수식은 다음과 같다.

$$
F_1 = 2\frac{PR}{P+R}
$$

여기에

$$
P=\frac{TP}{TP+FP}
$$

$$
R=\frac{TP}{TP+FN}
$$

을 대입하여 정리하면 다음과 같다.

$$
\boxed{ F_1 = \frac{2TP}{2TP+FP+FN} }
$$

즉 F1-score도 Confusion Matrix에서 직접 계산할 수 있다.

앞의 예제에 적용하면

$$
F_1 = \frac{ 2\times20 }{ 2\times20+10+20 }
$$

이다.

따라서

$$
F_1 = \frac{40}{70}
$$

이므로

$$
\boxed{ F_1\approx0.5714 }
$$

이다.

---

## 9.4 왜 Arithmetic Mean이 아니라 Harmonic Mean일까?

Precision과 Recall이 다음과 같다고 하자.

$$
P=0.9
$$

$$
R=0.1
$$

Arithmetic Mean(산술평균)은 다음과 같다.

$$
\frac{0.9+0.1}{2}=0.5
$$

반면 Harmonic Mean은 다음과 같다.

$$
F_1 = 2\frac{0.9\times0.1}{0.9+0.1}
$$

따라서

$$
\boxed{ F_1=0.18 }
$$

이다.

Precision이 90%로 높더라도 Recall이 10%로 낮기 때문에 F1-score는 18%에 불과하다.

즉 F1-score는 한쪽 지표의 높은 값만으로 전체 성능을 높게 평가하지 않는다.

---

# 10. F-beta Score

F1-score는 Precision과 Recall을 동일하게 중요하게 생각하는 경우에 사용할 수 있다.

하지만 실제 문제에서는 두 지표의 중요도가 다를 수 있다.

이러한 상황에서는 **F-beta Score**를 사용할 수 있다.

일반적인 수식은 다음과 같다.

$$
\boxed{ F_\beta = (1+\beta^2) \frac{ \operatorname{Precision}\times\operatorname{Recall} }{ \beta^2\operatorname{Precision}+\operatorname{Recall} } }
$$

여기서 $\beta>0$은 Precision과 Recall의 상대적인 중요도를 조절한다.

| Metric | $\beta$ | 의미 |
| --- | --- | --- |
| F0.5-score | 0.5 | Precision을 상대적으로 중요하게 평가 |
| F1-score | 1 | Precision과 Recall을 균형 있게 평가 |
| F2-score | 2 | Recall을 상대적으로 중요하게 평가 |

예를 들어 실제 Positive를 놓치는 것이 매우 중요한 문제라면 F2-score를 고려할 수 있다.

반대로 False Positive를 줄이는 것이 특히 중요하다면 F0.5-score를 고려할 수 있다.

다만 어떤 F-score를 선택할지는 실제 시스템에서 발생하는 오류의 비용을 고려하여 결정하는 것이 적절하다.

---

# 11. 네 가지 성능지표 계산 결과 비교

앞에서 정의한 Confusion Matrix는 다음과 같다.

| Actual \ Predicted | Negative | Positive |
| --- | --- | --- |
| Negative | 50 | 10 |
| Positive | 20 | 20 |

즉

$$
TP=20,\quad TN=50,\quad FP=10,\quad FN=20
$$

이다.

네 가지 지표를 계산하면 다음과 같다.

| Metric | Formula | Result |
| --- | --- | --- |
| Accuracy | $(TP+TN)/(TP+TN+FP+FN)$ | **70.0%** |
| Precision | $TP/(TP+FP)$ | **66.7%** |
| Recall | $TP/(TP+FN)$ | **50.0%** |
| F1-score | $2TP/(2TP+FP+FN)$ | **57.1%** |

이를 해석하면 다음과 같다.

**Accuracy = 70.0%**

전체 Sample의 70%를 올바르게 분류하였다.

**Precision = 66.7%**

Positive라고 예측한 Sample 중 약 66.7%가 실제 Positive이다.

**Recall = 50.0%**

실제 Positive 중 절반만 올바르게 탐지하였다.

**F1-score = 57.1%**

Precision과 Recall을 종합하면 약 57.1%의 F1-score를 가진다.

따라서 Accuracy만 확인했다면 전체 데이터를 70% 정확하게 분류하는 모델로 평가할 수 있다.

하지만 Recall을 함께 확인하면 **실제 Positive의 절반을 놓치고 있다는 중요한 문제**를 발견할 수 있다.

이처럼 여러 Metrics를 함께 확인하는 것이 중요하다.

# 15. Multiclass Classification에서는 어떻게 사용할까?

지금까지는 Binary Classification을 기준으로 설명하였다.

하지만 Multiclass Classification에서도 동일한 개념을 사용할 수 있다.

예를 들어 Iris Dataset은 다음 세 개의 Class를 가진다.

```text
Class 0 : Setosa
Class 1 : Versicolor
Class 2 : Virginica
```

Multiclass Classification에서는 각 Class를 하나씩 Positive로 간주하고 나머지 Class를 Negative로 취급하여 Precision, Recall, F1-score를 계산할 수 있다.

예를 들어 Setosa를 기준으로 한다면 다음과 같다.

```text
Positive Class : Setosa

Negative Classes:
    Versicolor
    Virginica
```

이러한 방식으로 Class별 지표를 계산할 수 있다.

전체 모델의 성능을 하나의 값으로 요약할 때는 다음 Averaging 방법을 사용할 수 있다.

| Averaging | 의미 |
| --- | --- |
| Macro | Class별 Metric을 동일한 비중으로 평균 |
| Micro | 전체 Class의 TP·FP·FN을 합산하여 계산 |
| Weighted | Class별 Support를 가중치로 평균 |

특히 데이터가 불균형하다면 `macro`와 `weighted` 결과를 함께 확인하는 것이 도움이 될 수 있다.

단, **단일 Label을 갖는 일반적인 Multiclass Classification에서는 Micro Precision, Micro Recall, Micro F1-score가 Accuracy와 동일**하다.

---

# 16. True Positive Rate와 False Positive Rate

앞에서 살펴본 Precision, Recall, F1-score는 하나의 Classification Threshold에서 계산되는 성능지표이다.

하지만 Classification Model은 Threshold에 따라 서로 다른 Prediction Result를 나타낼 수 있다.

예를 들어 모델이 Positive Class에 대한 Probability를 출력한다고 하자.

$$
P(Y=1\mid\mathbf{x})=0.7
$$

Threshold가 0.5라면 Positive로 분류한다.

반면 Threshold가 0.8이라면 Negative로 분류한다.

즉 동일한 모델이더라도 Threshold에 따라 TP, TN, FP, FN의 개수가 달라진다.

이러한 변화를 분석할 때 중요한 지표가 다음 두 가지이다.

- True Positive Rate(TPR)
- False Positive Rate(FPR)

---

## 16.1 True Positive Rate (TPR)

True Positive Rate는 실제 Positive인 Sample 중 모델이 Positive라고 올바르게 예측한 Sample의 비율이다.

$$
\boxed{ \mathrm{TPR} = \frac{TP}{TP+FN} }
$$

이는 앞에서 살펴본 Recall과 동일하다.

$$
\boxed{ \mathrm{TPR} = \mathrm{Recall} = \mathrm{Sensitivity} }
$$

즉 TPR은 모델이 실제 Positive Sample을 얼마나 잘 탐지하는지 나타낸다.

TPR이 높을수록 실제 Positive를 놓치는 비율이 낮아진다.

---

## 16.2 False Positive Rate (FPR)

False Positive Rate는 실제 Negative인 Sample 중 Positive라고 잘못 예측한 Sample의 비율이다.

$$
\boxed{ \mathrm{FPR} = \frac{FP}{FP+TN} }
$$

여기서 분모에 주목해야 한다.

$$
FP+TN
$$

은 실제 Negative인 전체 Sample 수이다.

따라서 FPR은 다음 질문에 답하는 지표이다.

> 실제 Negative인 데이터 중 모델이 얼마나 많이 Positive라고 잘못 판단했는가?

FPR은 Fall-out이라고도 불린다.

일반적으로 FPR이 낮을수록 False Positive가 적다는 의미이다.

---

## 16.3 Specificity (특이도)

FPR과 함께 이해해야 할 개념이 Specificity이다.

Specificity는 실제 Negative 중 Negative라고 올바르게 분류한 비율이다.

$$
\boxed{ \mathrm{Specificity} = \frac{TN}{TN+FP} }
$$

이는 True Negative Rate(TNR)라고도 불린다.

$$
\boxed{ \mathrm{TNR}=\mathrm{Specificity} }
$$

FPR과 TNR은 다음 관계를 가진다.

$$
\mathrm{FPR} = \frac{FP}{FP+TN}
$$

$$
\mathrm{TNR} = \frac{TN}{FP+TN}
$$

두 지표를 더하면

$$
\mathrm{FPR}+\mathrm{TNR} = \frac{FP+TN}{FP+TN}=1
$$

이다.

따라서

$$
\boxed{ \mathrm{FPR} = 1-\mathrm{Specificity} }
$$

이다.

---

## 16.4 기존 Confusion Matrix로 계산하기

앞에서 사용한 Confusion Matrix는 다음과 같다.

| Actual \ Predicted | Negative | Positive |
| --- | --- | --- |
| Negative | 50 (TN) | 10 (FP) |
| Positive | 20 (FN) | 20 (TP) |

따라서

$$
TP=20,\quad TN=50,\quad FP=10,\quad FN=20
$$

이다.

**TPR**

$$
\mathrm{TPR} = \frac{20}{20+20}
$$

$$
\boxed{ \mathrm{TPR}=0.5 }
$$

**FPR**

$$
\mathrm{FPR} = \frac{10}{10+50}
$$

$$
\boxed{ \mathrm{FPR}\approx0.167 }
$$

**Specificity**

$$
\mathrm{Specificity} = \frac{50}{50+10}
$$

$$
\boxed{ \mathrm{Specificity}\approx0.833 }
$$

즉 모델은 실제 Positive의 50%를 탐지하고, 실제 Negative의 약 16.7%를 Positive라고 잘못 분류하였다.

---

## 16.5 Precision·TPR·FPR 비교

세 지표의 차이는 분모에서 나타난다.

| Metric | Formula | 기준 |
| --- | --- | --- |
| Precision | $TP/(TP+FP)$ | Predicted Positive |
| TPR (Recall) | $TP/(TP+FN)$ | Actual Positive |
| FPR | $FP/(FP+TN)$ | Actual Negative |
| Specificity | $TN/(TN+FP)$ | Actual Negative |

Precision은 Positive라고 예측한 결과의 신뢰성을 평가한다.

TPR은 실제 Positive를 얼마나 많이 탐지했는지 평가한다.

FPR은 실제 Negative를 얼마나 많이 잘못 탐지했는지 평가한다.

이 세 가지 지표는 다음에 살펴볼 PR Curve와 ROC Curve를 이해하는 기반이 된다.

---

# 17. Precision–Recall Curve (PR Curve)

Precision–Recall Curve는 Classification Threshold를 변화시키면서 Precision과 Recall의 관계를 나타낸 그래프이다.

앞에서 살펴본 Precision–Recall Trade-off를 하나의 그래프로 표현한 것이다.

PR Curve는 다음과 같이 구성된다.

- X-axis: Recall
- Y-axis: Precision

즉 각각의 Threshold에서 Precision과 Recall을 계산하고, 그 결과를 그래프에 나타낸다.

$$
\boxed{ \mathrm{PR\ Curve} = (\mathrm{Recall},\mathrm{Precision}) }
$$

PR Curve는 주로 Binary Classification에서 사용된다.

---

## 17.1 PR Curve가 필요한 이유

일반적인 Precision과 Recall은 하나의 Threshold를 기준으로 계산한다.

예를 들어

$$
t=0.5
$$

를 사용한다면 해당 Threshold에서 하나의 Precision과 Recall 값을 얻는다.

하지만 Threshold를 변경하면 두 지표도 달라질 수 있다.

```text
Classification Threshold
          │
          ▼
     Prediction 변경
          │
          ▼
 Confusion Matrix 변경
          │
          ├── Precision 변경
          │
          └── Recall 변경
          │
          ▼
       PR Curve
```

따라서 PR Curve는 특정 Threshold 하나에 의존하지 않고 여러 Threshold에서 모델이 어떤 Precision–Recall 관계를 나타내는지 확인할 수 있다.

---

## 17.2 PR Curve 계산 예제

다음과 같은 Binary Classification Dataset을 생각하자.

전체 Sample은 100개이며, 실제 Class Distribution은 다음과 같다.

```text
Actual Negative : 60
Actual Positive : 40
```

모델이 Positive Probability를 다음과 같이 출력했다고 가정하자.

| 실제 Label | Sample 수 | Positive Score |
| --- | --- | --- |
| Negative | 50 | 0.1 |
| Negative | 10 | 0.6 |
| Positive | 20 | 0.4 |
| Positive | 20 | 0.9 |

이 Score는 개념을 설명하기 위해 설정한 가상의 모델 출력이다.

Prediction Rule은 다음과 같다.

$$
\boxed{ \hat y= \begin{cases} 1,&s(x)\ge t\\ 0,&s(x)<t \end{cases} }
$$

여기서 $s(x)$는 Positive Class에 대한 Score이고, $t$는 Threshold이다.

Threshold를 변화시키면 다음과 같은 결과를 얻는다.

| Threshold | TP | FP | FN | TN |
| --- | --- | --- | --- | --- |
| 0.8 | 20 | 0 | 20 | 60 |
| 0.5 | 20 | 10 | 20 | 50 |
| 0.3 | 40 | 10 | 0 | 50 |
| 0.05 | 40 | 60 | 0 | 0 |

특히 Threshold가 0.5인 경우 앞에서 사용한 Confusion Matrix와 정확히 일치한다.

---

## 17.3 Threshold에 따른 Precision과 Recall

각 Threshold에서 Precision과 Recall을 계산하면 다음과 같다.

| Threshold | Precision | Recall |
| --- | --- | --- |
| 0.8 | 1.000 | 0.500 |
| 0.5 | 0.667 | 0.500 |
| 0.3 | 0.800 | 1.000 |
| 0.05 | 0.400 | 1.000 |

예를 들어 Threshold가 0.8일 때는 높은 Score를 가진 Positive Sample 20개만 Positive로 판단한다.

따라서

$$
\mathrm{Precision} = \frac{20}{20+0}=1
$$

$$
\mathrm{Recall} = \frac{20}{20+20}=0.5
$$

이다.

반면 Threshold를 0.3으로 낮추면 실제 Positive 40개를 모두 탐지한다.

따라서

$$
\mathrm{Recall}=1
$$

이 된다.

하지만 Negative Sample 10개도 Positive로 잘못 분류한다.

따라서

$$
\mathrm{Precision} = \frac{40}{40+10}=0.8
$$

이다.

이 예제에서 중요한 사실은 **Threshold를 낮추면 Recall은 증가하거나 유지되지만, Precision은 반드시 감소하는 것은 아니라는 점**이다.

추가로 포함되는 Sample의 실제 Class에 따라 Precision이 증가하거나 감소할 수 있다.

---

## 17.4 PR Curve의 해석

PR Curve에서 이상적인 모델은 Precision과 Recall이 모두 1에 가까운 성능을 나타낸다.

따라서 그래프의 오른쪽 위에 가까운 영역이 일반적으로 좋은 성능을 의미한다.

$$
\boxed{ (\mathrm{Recall},\mathrm{Precision})=(1,1) }
$$

은 모든 Positive Sample을 탐지하면서 False Positive가 없는 경우이다.

하지만 PR Curve는 실제 모델의 Score Distribution에 따라 계단 형태나 불규칙한 형태를 가질 수 있다.

또한 Positive Sample이 매우 적으면 소수의 False Positive만 발생하더라도 Precision이 크게 감소할 수 있다.

이러한 특성 때문에 PR Curve는 Class Imbalance가 존재하는 Classification에서 특히 유용하다.

---

# 18. Average Precision (AP)

PR Curve는 다양한 Threshold에서 Precision과 Recall이 어떻게 변화하는지 보여준다.

그러나 여러 모델의 PR Curve를 하나의 숫자로 비교하고 싶을 수 있다.

이때 사용하는 대표적인 지표가 **Average Precision(AP)** 이다.

AP는 Recall이 증가하는 구간을 가중치로 사용하여 Precision을 종합한 값이다.

scikit-learn에서는 다음과 같이 정의한다.

$$
\boxed{ \mathrm{AP} = \sum_n (R_n-R_{n-1})P_n }
$$

여기서

- $P_n$: n번째 Operating Point의 Precision
- $R_n$: n번째 Operating Point의 Recall
- $R_n-R_{n-1}$: Recall의 증가량

이다.

---

## 18.1 AP의 의미

AP는 여러 Threshold에서 얻은 Precision을 Recall 증가량에 따라 가중 평균하여 요약한 지표이다.

일반적으로 AP가 높을수록 여러 Recall 수준에서 높은 Precision을 유지한다는 의미이다.

이번 예제의 가상 Prediction Score에서 계산하면 다음과 같다.

$$
\boxed{ \mathrm{AP}=0.9 }
$$

즉 해당 모델은 PR Curve 전반에서 비교적 높은 Precision을 나타낸다.

단, AP의 수치를 해석할 때는 Positive Class의 비율도 고려해야 한다.

Random Ranking의 기대 PR 기준 수준은 대체로 Positive Prevalence에 해당하기 때문이다.

---

## 18.2 AP와 PR-AUC는 완전히 같을까?

AUC는 Area Under the Curve의 약자이며, 그래프 아래의 면적을 의미한다.

PR Curve에 대해서도 AUC를 계산할 수 있다.

그러나 scikit-learn의 `average_precision_score()`에서 계산하는 AP와 `auc(recall, precision)`으로 계산하는 Trapezoidal PR-AUC는 일반적으로 동일하지 않다.

**Average Precision**

$$
\boxed{ \mathrm{AP} = \sum_n(R_n-R_{n-1})P_n }
$$

**Trapezoidal PR-AUC**

인접한 PR Curve Point 사이를 선형적으로 연결한 뒤 Trapezoidal Rule로 면적을 계산한다.

두 방법은 계산 방식이 다르므로 값도 달라질 수 있다.

따라서 논문이나 모델 평가 결과에서 PR-AUC라는 용어를 사용할 때는 정확히 어떤 계산 방법을 사용했는지 확인해야 한다.

---

# 19. Receiver Operating Characteristic (ROC Curve)

ROC Curve는 **True Positive Rate와 False Positive Rate의 관계를 나타낸 그래프**이다.

ROC는 Receiver Operating Characteristic의 약자이다.

Classification Threshold를 변화시키면서 각 Threshold의 TPR과 FPR을 계산한다.

일반적으로 다음과 같이 구성된다.

- X-axis: False Positive Rate (FPR)
- Y-axis: True Positive Rate (TPR)

따라서

$$
\boxed{ \mathrm{ROC\ Curve} = (\mathrm{FPR},\mathrm{TPR}) }
$$

이다.

여기서 TPR은 Recall과 동일하다.

$$
\boxed{ \mathrm{TPR}=\mathrm{Recall} }
$$

---

## 19.1 ROC Curve가 필요한 이유

하나의 Classification Threshold에서는 TPR과 FPR을 각각 하나의 값으로 얻는다.

하지만 Threshold를 변화시키면 TPR과 FPR 역시 달라진다.

Threshold가 낮아지면 더 많은 Sample을 Positive로 분류한다.

따라서 일반적으로

- TPR은 증가하거나 유지된다.
- FPR도 증가하거나 유지된다.

반대로 Threshold를 높이면 Positive로 판단하는 Sample이 줄어든다.

따라서 TPR과 FPR은 감소하거나 유지된다.

이러한 관계를 그래프로 표현한 것이 ROC Curve이다.

---

## 19.2 ROC Curve 계산 예제

앞에서 사용한 100개 Sample 예제를 다시 살펴보자.

| Threshold | TP | FP | FN | TN |
| --- | --- | --- | --- | --- |
| 0.8 | 20 | 0 | 20 | 60 |
| 0.5 | 20 | 10 | 20 | 50 |
| 0.3 | 40 | 10 | 0 | 50 |
| 0.05 | 40 | 60 | 0 | 0 |

TPR과 FPR을 계산하면 다음과 같다.

| Threshold | TPR | FPR |
| --- | --- | --- |
| 0.8 | 0.500 | 0.000 |
| 0.5 | 0.500 | 0.167 |
| 0.3 | 1.000 | 0.167 |
| 0.05 | 1.000 | 1.000 |

예를 들어 Threshold가 0.5인 경우

$$
\mathrm{TPR} = \frac{20}{20+20}=0.5
$$

이며

$$
\mathrm{FPR} = \frac{10}{10+50}\approx0.167
$$

이다.

따라서 ROC Curve에 다음 점을 표시할 수 있다.

$$
\boxed{ (\mathrm{FPR},\mathrm{TPR}) = (0.167,0.5) }
$$

각 Threshold에서 얻은 점들을 연결하면 ROC Curve를 구성할 수 있다.

실제 ROC Curve에는 모든 고유 Score를 기준으로 얻은 Operating Point와 양 끝점도 포함된다.

---

## 19.3 ROC Curve의 해석

ROC Curve에서 이상적인 모델은 다음 지점을 지난다.

$$
\boxed{ (\mathrm{FPR},\mathrm{TPR})=(0,1) }
$$

이 지점은 다음 두 조건을 만족한다.

- FPR = 0: 실제 Negative를 Positive라고 잘못 판단하지 않음
- TPR = 1: 실제 Positive를 모두 탐지함

따라서 ROC Curve는 왼쪽 위에 가까울수록 일반적으로 좋은 분류 성능을 나타낸다.

반대로 Random Ranking에 해당하는 기준선은 일반적으로 다음과 같은 대각선으로 표현된다.

$$
\boxed{ \mathrm{TPR}=\mathrm{FPR} }
$$

이 기준선은 Positive와 Negative를 구분하는 Ranking 능력이 없는 모델의 평균적인 동작을 나타낸다.

---

# 20. ROC-AUC (Area Under the ROC Curve)

ROC Curve는 Threshold에 따른 TPR과 FPR의 변화를 시각적으로 보여준다.

하지만 여러 모델의 ROC Curve를 하나의 값으로 비교하고 싶을 수 있다.

이때 사용하는 지표가 ROC-AUC이다.

AUC는 Area Under the Curve의 약자이다.

ROC-AUC는 ROC Curve 아래의 면적이다.

$$
\boxed{ \mathrm{ROC\text{-}AUC} = \int_0^1\mathrm{TPR}(u)\,du }
$$

여기서 $u$는 FPR을 의미한다.

ROC-AUC는 0부터 1 사이의 값을 가지며, 일반적으로 값이 높을수록 Positive와 Negative를 구분하는 Ranking 능력이 좋다고 해석한다.

---

## 20.1 ROC-AUC의 해석

| ROC-AUC | 의미 |
| --- | --- |
| 1.0 | 완벽한 Positive–Negative Ranking |
| 0.5 | Random Ranking 수준 |
| 0.5보다 낮음 | Positive와 Negative의 Ranking이 반대 방향에 가까움 |

다만 이는 개념적인 해석이며, 실제 모델의 유용성은 적용 분야와 Class Distribution, Threshold, Error Cost 등을 고려해야 한다.

ROC-AUC는 단순한 Classification Accuracy와 다르다.

또한 **ROC-AUC가 높다고 특정 Threshold에서 Precision이나 Recall이 반드시 높다는 뜻도 아니다.**

---

## 20.2 ROC-AUC의 또 다른 의미

ROC-AUC는 임의의 Positive Sample과 Negative Sample을 하나씩 선택했을 때, Positive Sample에 더 높은 Prediction Score를 부여할 Ranking 확률로 해석할 수 있다.

Score가 같은 경우에는 Tie를 절반의 기여로 처리한다.

이를 개념적으로 표현하면 다음과 같다.

$$
\boxed{ \mathrm{AUC} = P(s(X^+)>s(X^-)) + \frac12P(s(X^+)=s(X^-)) }
$$

여기서

- $X^+$: Positive Sample
- $X^-$: Negative Sample
- $s(\cdot)$: 모델의 Positive Score

이다.

따라서 ROC-AUC는 모델의 특정 Threshold가 아니라 **Positive와 Negative를 얼마나 잘 구분하여 순위를 매기는가**를 평가하는 지표로 이해할 수 있다.

---

## 20.3 ROC-AUC 계산 예제

앞에서 사용한 100개 Sample과 Prediction Score를 이용하면 다음 값을 얻는다.

$$
\boxed{ \mathrm{ROC\text{-}AUC}\approx0.9167 }
$$

이는 해당 가상 모델이 Positive Sample과 Negative Sample을 구분하는 Ranking 측면에서 비교적 높은 성능을 나타낸다는 의미이다.

다만 Threshold 0.5에서의 Recall은 0.5였다.

즉 ROC-AUC가 높아도 선택한 Threshold에서 실제 Positive의 절반을 놓칠 수 있다.

따라서 ROC-AUC만 보고 모델의 최종 Classification Performance를 판단하는 것은 적절하지 않다.

---

# 21. PR Curve와 ROC Curve의 차이

PR Curve와 ROC Curve는 모두 Classification Threshold를 변화시키면서 모델의 성능을 평가한다.

그러나 그래프의 축과 평가 관점이 다르다.

| 구분 | PR Curve | ROC Curve |
| --- | --- | --- |
| X-axis | Recall | FPR |
| Y-axis | Precision | TPR |
| 주요 관점 | Positive 예측의 신뢰성 및 탐지율 | Positive 탐지율과 False Alarm Rate |
| 이상적인 지점 | (1, 1) | (0, 1) |
| 대표적인 요약 지표 | AP, PR-AUC | ROC-AUC |
| Class Imbalance | Positive가 희소할 때 특히 유용 | Negative가 매우 많으면 FP 영향이 덜 두드러질 수 있음 |

---

## 21.1 Class Imbalance에서 PR Curve가 중요한 이유

예를 들어 다음과 같은 Dataset이 있다고 하자.

```text
Negative : 990 Samples
Positive : 10 Samples
```

실제 Negative가 990개이므로 FPR의 분모는 매우 크다.

만약 FP가 10개 발생했다면

$$
\mathrm{FPR} = \frac{10}{990} \approx0.0101
$$

이다.

즉 FPR은 약 1.01%에 불과하다.

하지만 모델이 Positive 10개를 모두 탐지했다고 하자.

$$
TP=10
$$

이 경우 Precision은 다음과 같다.

$$
\mathrm{Precision} = \frac{10}{10+10}
$$

따라서

$$
\boxed{ \mathrm{Precision}=0.5 }
$$

이다.

즉 실제 Positive를 모두 찾았지만 Positive라고 예측한 Sample의 절반은 False Positive이다.

이 상황에서 ROC Curve상의 FPR은 매우 낮아 보일 수 있다.

반면 PR Curve에서는 Precision이 50%라는 사실이 명확하게 드러난다.

따라서 Positive Class가 매우 희소한 문제에서는 PR Curve를 함께 확인하는 것이 유용하다.

---

## 21.2 어떤 Curve를 사용해야 할까?

**PR Curve**

Positive Prediction의 신뢰성과 실제 Positive의 탐지율을 함께 평가하는 것이 중요한 경우 유용하다.

예를 들어 Positive Class가 매우 희소하거나 Positive라고 판정한 결과의 정확성이 중요한 경우이다.

**ROC Curve**

여러 Threshold에서 Positive Detection과 False Positive Rate 사이의 관계를 평가할 때 유용하다.

예를 들어 특정 Sensitivity에서 허용 가능한 False Positive Rate를 확인하려는 경우이다.

두 Curve 중 하나가 항상 우수한 것은 아니다.

**평가하려는 Class Distribution과 오류 비용에 따라 적절한 Curve를 선택하거나 함께 사용하는 것이 중요하다.**

---

# 22. Python 실습: PR Curve와 ROC Curve 구현

scikit-learn에서는 PR Curve와 ROC Curve를 계산하는 함수를 제공한다.

대표적인 함수는 다음과 같다.

| Function | 역할 |
| --- | --- |
| `precision_recall_curve()` | Threshold별 Precision과 Recall 계산 |
| `average_precision_score()` | Average Precision 계산 |
| `roc_curve()` | Threshold별 FPR과 TPR 계산 |
| `roc_auc_score()` | ROC-AUC 계산 |
| `auc()` | 주어진 Curve Point에 대해 Trapezoidal AUC 계산 |

중요한 점은 PR Curve와 ROC Curve를 계산할 때 **예측된 Class Label이 아니라 Prediction Score가 필요하다**는 것이다.

---

## 22.1 Dataset 구성

앞에서 사용한 Confusion Matrix와 일치하도록 예제 Score를 구성한다.

```python
import numpy as np

# Actual Labels
y_true = np.array(
    [0] * 50 +
    [0] * 10 +
    [1] * 20 +
    [1] * 20
)

# Positive Class Scores
# 개념 설명을 위해 설정한 가상 점수
y_score = np.array(
    [0.1] * 50 +
    [0.6] * 10 +
    [0.4] * 20 +
    [0.9] * 20
)

# Threshold = 0.5
y_pred = (y_score >= 0.5).astype(int)
```

이때 생성되는 Confusion Matrix는 다음과 같다.

```text
[[50 10]
 [20 20]]
```

따라서 기존 본문에서 사용한 Classification 예제와 동일한 결과를 얻는다.

---

## 22.2 ROC Curve 구현

```python
import matplotlib.pyplot as plt

from sklearn.metrics import (
    roc_curve,
    roc_auc_score
)

fpr, tpr, roc_thresholds = roc_curve(
    y_true,
    y_score
)

roc_auc = roc_auc_score(
    y_true,
    y_score
)

plt.figure(figsize=(7, 5))

plt.plot(
    fpr,
    tpr,
    marker="o",
    label=f"ROC-AUC = {roc_auc:.4f}"
)

plt.plot(
    [0, 1],
    [0, 1],
    linestyle="--",
    label="Random Classifier"
)

plt.xlabel("False Positive Rate")
plt.ylabel("True Positive Rate")
plt.title("ROC Curve")

plt.legend()
plt.grid(alpha=0.3)
plt.show()

print(f"ROC-AUC: {roc_auc:.4f}")
```

출력:

```text
ROC-AUC: 0.9167
```

ROC Curve의 X-axis는 FPR, Y-axis는 TPR이다.

그래프가 왼쪽 위에 가까울수록 여러 Threshold에서 높은 TPR과 낮은 FPR을 보인다는 의미이다.

---

## 22.3 PR Curve 구현

```python
from sklearn.metrics import (
    precision_recall_curve,
    average_precision_score
)

precision, recall, pr_thresholds = (
    precision_recall_curve(
        y_true,
        y_score
    )
)

ap = average_precision_score(
    y_true,
    y_score
)

plt.figure(figsize=(7, 5))

plt.step(
    recall,
    precision,
    where="post",
    label=f"AP = {ap:.4f}"
)

plt.axhline(
    y=y_true.mean(),
    linestyle="--",
    label="Positive Prevalence"
)

plt.xlabel("Recall")
plt.ylabel("Precision")
plt.title("Precision-Recall Curve")

plt.legend()
plt.grid(alpha=0.3)
plt.show()

print(f"Average Precision: {ap:.4f}")
```

출력:

```text
Average Precision: 0.9000
```

여기서 `y_true.mean()`은 전체 Sample 중 Positive Sample의 비율이다.

이번 예제에서는

$$
\frac{40}{100}=0.4
$$

이다.

따라서 그래프에 0.4의 기준선을 표시한다.

이는 Random Ranking의 기대 Precision 수준을 이해하기 위한 참고선이다.

---

## 22.4 ROC-AUC와 AP 결과 비교

이번 예제의 결과를 정리하면 다음과 같다.

| Metric | Result |
| --- | --- |
| Accuracy (Threshold = 0.5) | 0.7000 |
| Precision (Threshold = 0.5) | 0.6667 |
| Recall (Threshold = 0.5) | 0.5000 |
| F1-score (Threshold = 0.5) | 0.5714 |
| ROC-AUC | 0.9167 |
| Average Precision | 0.9000 |

여기서 Accuracy, Precision, Recall, F1-score는 Threshold 0.5를 기준으로 계산한 값이다.

반면 ROC-AUC와 AP는 여러 Threshold를 고려한 Prediction Score의 Ranking Performance를 요약한 값이다.

따라서 두 종류의 Metric을 구분해야 한다.

```text
Classification Model
        │
        ▼
  Prediction Score
        │
        ├── Threshold 적용
        │        │
        │        ▼
        │   Predicted Label
        │        │
        │        ├── Accuracy
        │        ├── Precision
        │        ├── Recall
        │        └── F1-score
        │
        └── Threshold 변화
                 │
                 ├── PR Curve
                 │      └── AP
                 │
                 └── ROC Curve
                        └── ROC-AUC
```

즉 단일 Threshold에서의 Classification Performance와 여러 Threshold에서의 Ranking Performance는 서로 다른 관점의 평가이다.

---

### 내용 핵심 정리

**FPR**

실제 Negative 중 Positive라고 잘못 판단한 비율이다.

$$
\boxed{ \mathrm{FPR} = \frac{FP}{FP+TN} }
$$

**TPR**

실제 Positive 중 올바르게 탐지한 비율이며 Recall과 동일하다.

$$
\boxed{ \mathrm{TPR} = \frac{TP}{TP+FN} }
$$

**PR Curve**

Threshold에 따른 Precision과 Recall의 관계를 나타낸다.

$$
\boxed{ (\mathrm{Recall},\mathrm{Precision}) }
$$

**ROC Curve**

Threshold에 따른 FPR과 TPR의 관계를 나타낸다.

$$
\boxed{ (\mathrm{FPR},\mathrm{TPR}) }
$$

**Average Precision**

PR Curve의 Precision을 Recall 증가량으로 가중하여 요약한다.

$$
\boxed{ \mathrm{AP} = \sum_n(R_n-R_{n-1})P_n }
$$

**ROC-AUC**

ROC Curve 아래의 면적이며, Positive와 Negative를 구분하는 Ranking 능력을 나타낸다.

$$
\boxed{ \mathrm{ROC\text{-}AUC} = \int_0^1\mathrm{TPR}(u)\,du }
$$

PR Curve와 ROC Curve 모두 중요한 Classification Evaluation 도구이지만 평가하는 관점은 다르다.

따라서 실제 Application의 목적과 Class Distribution에 따라 적절한 지표를 선택하는 것이 중요하다.

# 23. 어떤 Metric을 사용해야 할까?

Classification Model을 평가할 때 어떤 Metric이 항상 가장 좋은 것은 아니다.

실제 문제에서 무엇을 중요하게 생각하는지에 따라 적절한 지표가 달라진다.

| 상황 | 중요하게 고려할 Metric |
| --- | --- |
| 전체적인 분류 성능 | Accuracy |
| False Positive를 줄여야 하는 경우 | Precision |
| False Negative를 줄여야 하는 경우 | Recall |
| Precision과 Recall의 균형이 중요한 경우 | F1-score |
| Recall을 더 중요하게 평가하는 경우 | F2-score |
| Precision을 더 중요하게 평가하는 경우 | F0.5-score |

예를 들어 이상 상태를 놓치는 것이 매우 중요한 시스템에서는 Recall을 중요하게 평가할 수 있다.

반대로 잘못된 이상 판정으로 인해 큰 비용이 발생하는 시스템에서는 Precision이 중요할 수 있다.

따라서 Classification Metrics는 단순히 숫자가 높은 모델을 선택하기 위한 도구가 아니라, **어떤 종류의 예측 오류가 발생하고 있는지 파악하기 위한 지표**로 이해해야 한다.

---

# 24. 핵심 공식 총정리

### Accuracy

전체 Sample 중 올바르게 예측한 비율이다.

$$
\boxed{ \operatorname{Accuracy} = \frac{TP+TN}{TP+TN+FP+FN} }
$$

### Precision

Positive라고 예측한 Sample 중 실제 Positive의 비율이다.

$$
\boxed{ \operatorname{Precision} = \frac{TP}{TP+FP} }
$$

### Recall

실제 Positive 중 올바르게 탐지한 비율이다.

$$
\boxed{ \operatorname{Recall} = \frac{TP}{TP+FN} }
$$

### F1-score

Precision과 Recall의 조화평균이다.

$$
\boxed{ F_1 = 2\frac{PR}{P+R} }
$$

또는

$$
\boxed{ F_1 = \frac{2TP}{2TP+FP+FN} }
$$

이다.

### F-beta Score

Precision과 Recall의 상대적인 중요도를 조절한다.

$$
\boxed{ F_\beta = (1+\beta^2) \frac{PR}{\beta^2P+R} }
$$

# 25. 네 가지 Metrics 암기 방법

다음 네 문장을 기억하면 된다.

**Accuracy**

> 전체 데이터 중 몇 개를 맞혔는가?

**Precision**

> Positive라고 예측한 것 중 몇 개가 진짜 Positive인가?

**Recall**

> 실제 Positive 중 몇 개를 찾아냈는가?

**F1-score**

> Precision과 Recall을 얼마나 균형 있게 달성했는가?

수식으로 정리하면 다음과 같다.

```text
Accuracy
    │
    ▼
전체 Sample 기준
    │
    ▼
(TP + TN) / Total


Precision
    │
    ▼
Predicted Positive 기준
    │
    ▼
TP / (TP + FP)


Recall
    │
    ▼
Actual Positive 기준
    │
    ▼
TP / (TP + FN)


F1-score
    │
    ▼
Precision + Recall
    │
    ▼
Harmonic Mean
```

특히 Precision과 Recall은 분자에 모두 TP가 존재한다.

따라서 **분모가 무엇을 의미하는지** 이해하는 것이 가장 중요하다.

# 26. 최종 정리

Classification Model의 성능을 평가할 때는 Accuracy, Precision, Recall, F-score가 대표적으로 사용된다.

이 지표들은 Confusion Matrix를 기반으로 계산할 수 있다.

Confusion Matrix는 Actual Label과 Predicted Label을 비교하여 TP, TN, FP, FN으로 분류한다.

Accuracy는 전체 Sample 중 올바르게 예측한 비율을 나타낸다.

하지만 Imbalanced Dataset에서는 Accuracy가 높더라도 관심 있는 Class를 제대로 탐지하지 못할 수 있다.

따라서 Precision과 Recall을 함께 고려해야 한다.

Precision은 모델이 Positive라고 예측한 결과의 신뢰성을 나타낸다.

반면 Recall은 실제 Positive를 얼마나 찾아냈는지 나타낸다.

두 지표는 Classification Threshold에 따라 Trade-off가 발생할 수 있다.

이러한 두 지표를 종합적으로 평가하기 위해 F1-score를 사용할 수 있다.

F1-score는 Precision과 Recall의 Harmonic Mean으로 계산되며, 두 지표 중 하나가 매우 낮으면 F1-score도 낮아지는 특성이 있다.

따라서 Classification Model을 평가할 때는 하나의 Metric만 확인하기보다 **여러 지표를 함께 분석하여 모델의 오류 특성을 파악하는 것**이 중요하다.

---

## 핵심 요약

> Accuracy는 전체 정답률, Precision은 Positive라고 예측한 결과의 신뢰성, Recall은 실제 Positive를 찾아낸 비율이다. F1-score는 Precision과 Recall의 조화평균으로 두 지표를 종합적으로 평가한다. 특히 Class Imbalance가 존재하는 경우에는 Accuracy만으로 모델의 성능을 판단하기 어렵기 때문에 Precision, Recall, F1-score를 함께 확인하는 것이 중요하다.
