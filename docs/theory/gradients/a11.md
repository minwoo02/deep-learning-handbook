# Gradient Descent와 Learning Rate: Linear Regression과 Logistic Regression까지

Machine Learning과 Deep Learning에서 모델을 학습한다는 것은 결국 **좋은 Parameter를 찾는 과정**이다.

예를 들어 Model Parameter를 $\mathbf{w}$라고 하면 우리가 원하는 것은 Loss Function을 가장 작게 만드는 Parameter이다.

이를 수학적으로 표현하면

$$
\mathbf{w}^* \in \arg\min_{\mathbf{w}} L(\mathbf{w};X,y)
$$

이다.

여기서

- $X$ : Input Data
- $y$ : Target
- $\mathbf{w}$ : Model Parameter
- $L$ : Loss Function
- $\mathbf{w}^*$ : Loss를 최소화하는 최적 Parameter

이다.

그렇다면 가장 중요한 질문은 다음과 같다.

> **현재 Parameter에서 어느 방향으로 얼마나 이동해야 Loss가 줄어드는가?**

이를 해결하는 대표적인 방법이 **Gradient Descent**이다.

---

# 1. Gradient란?

Gradient는 다변수 함수에서 함수값이 가장 빠르게 증가하는 방향을 나타내는 Vector이다.

Loss Function이

$$
L(\mathbf{w})
$$

라면 Gradient는

$$
\nabla_{\mathbf{w}}L
$$

로 표현한다.

Gradient가 가리키는 방향은

```text
Loss가 가장 빠르게 증가하는 방향
```

이다.

하지만 우리의 목표는 Loss를 줄이는 것이다.

따라서 반대 방향으로 이동한다.

```text
Gradient
→ Loss 증가 방향

-Gradient
→ Loss 감소 방향
```

## Gradient 계산의 세 가지 방법: Numerical, Symbolic, Automatic Differentiation

딥러닝에서 모델을 학습한다는 것은 **Loss Function을 최소화하는 Parameter를 찾는 과정**이다.

이때 Parameter를 어느 방향으로 얼마나 변경해야 하는지 판단하기 위해 사용하는 것이 **Gradient(기울기)** 이다.

예를 들어 손실 함수가 $L(w)$라면 Parameter $w$에 대한 미분값은 다음과 같다.

$$
\frac{dL}{dw}
$$

이는 $w$가 조금 변할 때 Loss가 얼마나 빠르게 변하는지를 나타낸다.

Parameter가 여러 개라면 각각의 편미분을 모아 Gradient Vector로 표현한다.

$$
\nabla_{\mathbf{w}}L = \begin{bmatrix} \frac{\partial L}{\partial w_1}\\ \frac{\partial L}{\partial w_2}\\ \vdots\\ \frac{\partial L}{\partial w_n} \end{bmatrix}
$$

그렇다면 컴퓨터는 이 Gradient를 어떻게 계산할까?

대표적으로 다음 세 가지 방법이 존재한다.

1. **Numerical Differentiation** — 수치 미분
2. **Symbolic Differentiation** — 기호 미분
3. **Automatic Differentiation** — 자동 미분

---

### 1. Numerical Differentiation (수치 미분)

Numerical Differentiation은 **입력값을 조금 변화시켰을 때 함수값이 얼마나 달라지는지를 이용하여 미분값을 근사하는 방법**이다.

미분의 수학적 정의는 다음과 같다.

$$
f'(x) = \lim_{h\rightarrow0} \frac{f(x+h)-f(x)}{h}
$$

하지만 컴퓨터에서는 $h$를 무한히 0에 가깝게 만들 수 없다.

따라서 충분히 작은 값의 $h$를 사용하여 미분값을 근사한다.

대표적인 방법은 다음과 같다.

**① Forward Difference (전진 차분)**

$$
f'(x) \approx \frac{f(x+h)-f(x)}{h}
$$

**② Central Difference (중앙 차분)**

$$
f'(x) \approx \frac{f(x+h)-f(x-h)}{2h}
$$

Central Difference는 함수가 충분히 매끄러운 경우 일반적으로 Forward Difference보다 높은 정확도를 제공한다.

#### 예제

다음 함수를 생각해 보자.

$$
f(x)=x^2
$$

$x=3$에서의 기울기를 구하고 싶다고 하자.

Central Difference를 사용하면

$$
f'(3) \approx \frac{f(3+h)-f(3-h)}{2h}
$$

이다.

$h=0.01$로 설정하면

$$
f'(3) \approx \frac{3.01^2-2.99^2}{0.02}
$$

$$
= \frac{9.0601-8.9401}{0.02}
$$

$$
=6
$$

이다.

실제 미분값 역시

$$
f'(x)=2x
$$

이므로

$$
f'(3)=6
$$

이다.

이 예제에서는 정확히 같은 결과를 얻었다.

그러나 일반적인 함수에서는 근사 오차가 발생할 수 있다.

#### Numerical Differentiation의 한계

Numerical Differentiation에는 다음과 같은 문제가 존재한다.

- $h$가 너무 크면 미분값의 근사 오차가 증가할 수 있다.
- $h$가 너무 작으면 부동소수점 연산에서 반올림 및 상쇄 오차가 커질 수 있다.
- Parameter마다 함수값을 반복 계산해야 하므로 연산 비용이 증가한다.
- Parameter가 수백만 개 이상인 딥러닝 모델에서는 매우 비효율적이다.

따라서 Numerical Differentiation은 일반적으로 딥러닝 모델을 직접 학습시키기보다는 **Gradient Checking**에 활용한다.

Gradient Checking은 계산된 Gradient가 올바른지 검증하는 과정이다.

---

### 2. Analytical Gradient와 Symbolic Differentiation

**Analytical Gradient(해석적 기울기)** 는 수학적 미분 법칙에 따라 구한 기울기를 의미한다.

예를 들어

$$
f(x)=x^2+3x+1
$$

이라는 함수가 있다고 하자.

미분 법칙을 직접 적용하면

$$
f'(x)=2x+3
$$

이 된다.

이는 작은 변화량을 이용하여 근사한 결과가 아니라, 수학적 미분을 통해 얻은 정확한 도함수이다.

이처럼 컴퓨터가 함수의 수학적 표현식을 이용하여 새로운 도함수 표현식을 생성하는 방법을 **Symbolic Differentiation(기호 미분)** 이라고 한다.

즉 다음과 같이 구분할 수 있다.

**Analytical Gradient**

- 수학적 미분 법칙에 따라 정의되는 기울기이다.
- Numerical Differentiation으로 얻는 근사 기울기와 구분할 때 사용하는 표현이다.

**Symbolic Differentiation**

- 도함수의 수학적 표현식을 생성하는 계산 방법이다.
- 입력된 수식에 미분 법칙을 적용하여 새로운 수식을 만든다.
- Python의 `SymPy` 등이 대표적인 예이다.

따라서 Analytical Gradient와 Symbolic Differentiation은 밀접한 관계가 있지만 완전히 같은 개념은 아니다.

**Analytical Gradient는 수학적으로 구한 기울기를 가리키고, Symbolic Differentiation은 그 기울기의 표현식을 구하는 방법 중 하나**이다.

---

### 3. Automatic Differentiation (자동 미분)

Automatic Differentiation은 **각 연산의 미분 규칙과 Chain Rule(연쇄 법칙)을 이용하여 Gradient를 계산하는 방법**이다.

딥러닝에서 가장 중요하게 사용되는 방식이다.

PyTorch의 `autograd` 역시 Automatic Differentiation을 사용한다.

#### Chain Rule을 이용한 계산

다음 함수를 생각해 보자.

$$
f(x)=(x^2+1)^2
$$

이를 두 개의 연산으로 나누면

$$
a=x^2+1
$$

$$
f=a^2
$$

이다.

각 연산을 미분하면

$$
\frac{da}{dx}=2x
$$

$$
\frac{df}{da}=2a
$$

이다.

Chain Rule에 의해

$$
\frac{df}{dx} = \frac{df}{da} \frac{da}{dx}
$$

이므로

$$
=2a\cdot2x
$$

이다.

여기에 $a=x^2+1$을 대입하면

$$
\boxed{ f'(x)=4x(x^2+1) }
$$

을 얻는다.

Automatic Differentiation은 이처럼 **함수를 구성하는 개별 연산의 미분값을 계산하고, Chain Rule로 연결하여 최종 Gradient를 구한다.**

중요한 점은 전체 함수의 도함수 표현식을 새로 생성할 필요가 없다는 것이다.

---

### 4. PyTorch autograd 예제

PyTorch에서는 `requires_grad=True`를 설정하여 Tensor에 대한 Gradient 계산을 활성화할 수 있다.

```python
import torch

x = torch.tensor(3.0, requires_grad=True)

y = (x**2 + 1)**2

y.backward()

print(x.grad)
```

출력:

```text
tensor(120.)
```

수학적으로 확인해 보자.

$$
f'(x)=4x(x^2+1)
$$

이므로

$$
f'(3) = 4(3)(3^2+1)
$$

$$
=4\cdot3\cdot10
$$

$$
=120
$$

이다.

즉 PyTorch의 `autograd`가 계산한 Gradient는 수학적으로 구한 미분값과 일치한다.

여기서

- `requires_grad=True` : 연산에 대한 Gradient 추적을 활성화한다.
- `y.backward()` : 역방향으로 Gradient를 계산한다.
- `x.grad` : 계산된 Gradient를 저장한다.

---

### 5. Automatic Differentiation과 Backpropagation

딥러닝에서 사용하는 **Backpropagation(오차역전파법)** 은 Chain Rule을 이용하여 Neural Network의 Gradient를 효율적으로 계산하는 알고리즘이다.

PyTorch에서는 연산을 수행하면서 Computation Graph를 구성한다.

예를 들어

$$
x \rightarrow x^2 \rightarrow x^2+1 \rightarrow (x^2+1)^2
$$

와 같은 연산이 있다면, Backpropagation에서는 출력에서 입력 방향으로 Gradient를 전달한다.

$$
\frac{\partial L}{\partial x} = \frac{\partial L}{\partial a} \frac{\partial a}{\partial x}
$$

즉 각 연산의 Local Gradient를 Chain Rule로 연결한다.

이때 사용되는 것이 **Reverse-Mode Automatic Differentiation**이다.

따라서 두 개념은 다음과 같이 구분할 수 있다.

- **Automatic Differentiation:** 연산별 미분 규칙을 이용하여 미분값을 계산하는 기술
- **Backpropagation:** 신경망에서 Gradient를 효율적으로 계산하기 위해 Reverse-Mode Automatic Differentiation을 적용하는 알고리즘

즉 Backpropagation은 Automatic Differentiation과 밀접하게 연결된 개념이다.

---

### 6. Numerical Differentiation과 Automatic Differentiation은 다르다

두 방식 모두 컴퓨터에서 수치 연산을 수행하지만 Gradient를 구하는 원리가 다르다.

**Numerical Differentiation**

함수값을 직접 비교하여 기울기를 근사한다.

$$
f'(x) \approx \frac{f(x+h)-f(x-h)}{2h}
$$

**Automatic Differentiation**

각 연산의 미분 규칙과 Chain Rule을 이용한다.

$$
\frac{df}{dx} = \frac{df}{da} \frac{da}{dx}
$$

따라서 Automatic Differentiation은 수치 연산을 수행하지만 일반적으로 **Numerical Differentiation이라고 부르지 않는다.**

Automatic Differentiation은 미분 가능한 지점에서 수학적 도함수와 동일한 값을 부동소수점 정밀도 범위 내에서 계산한다.

반면 Numerical Differentiation은 유한한 $h$를 사용하는 근사 방법이므로 근사 오차가 존재한다.

---

### 7. ReLU처럼 미분할 수 없는 지점에서는?

딥러닝에서 자주 사용하는 ReLU 함수는 다음과 같다.

$$
\operatorname{ReLU}(x) = \max(0,x)
$$

미분하면

$$
\operatorname{ReLU}'(x) = \begin{cases} 0, & x<0\\ 1, & x>0 \end{cases}
$$

이다.

그러나 $x=0$에서는 좌미분계수와 우미분계수가 다르기 때문에 일반적인 의미의 미분값이 존재하지 않는다.

그렇다면 PyTorch의 `autograd`는 어떻게 처리할까?

PyTorch에서는 ReLU의 $x=0$에서 Gradient를 0으로 처리한다.

이는 해당 지점에서 사용하는 **Subgradient(부분기울기)** 중 하나이다.

따라서 `autograd`가 모든 지점에서 일반적인 의미의 정확한 도함수를 계산한다고 표현하는 것은 엄밀하게 정확하지 않다.

보다 정확하게는 다음과 같이 이해해야 한다.

> PyTorch의 `autograd`는 미분 가능한 지점에서는 Automatic Differentiation으로 도함수 값을 계산하고, 미분 불가능한 일부 지점에서는 정의된 Subgradient 또는 Framework Convention에 따라 Gradient를 계산한다.

### 8. 세 가지 미분 방법 비교

| 구분 | Numerical Differentiation | Symbolic Differentiation | Automatic Differentiation |
| --- | --- | --- | --- |
| 한국어 | 수치 미분 | 기호 미분 | 자동 미분 |
| 원리 | 함수값의 변화량 이용 | 도함수 수식 생성 | 미분 규칙과 Chain Rule 적용 |
| 결과 | 미분값의 근사 | 도함수 표현식 | 특정 입력에서의 미분값 |
| 근사 오차 | 존재 | 수학적 수식 자체에는 없음 | Finite Difference 근사 오차 없음 |
| 전체 도함수 표현식 생성 | 필요 없음 | 필요함 | 필요 없음 |
| 딥러닝 활용 | Gradient Checking | 수학적 분석 | 실제 Model Training |
| 대표 도구 | Finite Difference | SymPy | PyTorch autograd |

### 9. 왜 딥러닝에서는 Automatic Differentiation을 사용하는가?

딥러닝 모델에는 수많은 Parameter가 존재한다.

예를 들어 수백만 개의 Weight가 존재하는 Neural Network를 생각해 보자.

Numerical Differentiation을 이용한다면 각 Parameter를 조금씩 변화시키며 Loss를 반복 계산해야 한다.

반면 Reverse-Mode Automatic Differentiation은 Computation Graph를 이용하여 **하나의 Scalar Loss에서 수많은 Parameter로 향하는 Gradient를 효율적으로 계산할 수 있다.**

따라서 현대 Deep Learning Framework는 Automatic Differentiation을 핵심적인 학습 기능으로 사용한다.

PyTorch에서는 일반적으로 다음 순서로 학습을 진행한다.

```python
optimizer.zero_grad()

output = model(x)

loss = criterion(output, y)

loss.backward()

optimizer.step()
```

각 단계의 역할은 다음과 같다.

| 단계 | 역할 |
| --- | --- |
| `zero_grad()` | 이전 Gradient 초기화 |
| `model(x)` | Forward Propagation |
| `criterion()` | Loss 계산 |
| `backward()` | Automatic Differentiation을 이용한 Gradient 계산 |
| `step()` | 계산된 Gradient를 이용한 Parameter Update |

즉 **Automatic Differentiation은 Gradient를 계산하는 역할**을 담당하고, **Optimizer는 계산된 Gradient를 이용해 Parameter를 업데이트하는 역할**을 담당한다.

이 둘을 구분하는 것이 중요하다.

---

### 핵심 정리

컴퓨터에서 Gradient를 계산하는 대표적인 방법은 다음과 같다.

**① Numerical Differentiation**

- 함수값의 변화량으로 Gradient를 근사한다.
- Finite Difference를 사용한다.
- 주로 Gradient Checking에 활용된다.

**② Symbolic Differentiation**

- 미분 규칙을 적용하여 도함수의 수학적 표현식을 생성한다.
- Analytical Gradient를 구하는 방법 중 하나이다.

**③ Automatic Differentiation**

- 각 연산의 미분 규칙과 Chain Rule을 이용한다.
- 전체 도함수 표현식을 생성할 필요가 없다.
- PyTorch `autograd`가 대표적인 예이다.
- 딥러닝 모델의 Backpropagation에 사용된다.

따라서

**Numerical Differentiation은 기울기를 근사하고, Symbolic Differentiation은 미분식을 생성하며, Automatic Differentiation은 연산별 미분 규칙을 연결하여 기울기를 효율적으로 계산한다.**

---

### 한 문장으로 정리

**Numerical Differentiation은 함수값의 차이를 이용한 근사 미분이고, Symbolic Differentiation은 도함수 표현식을 생성하는 방법이며, Automatic Differentiation은 Chain Rule을 이용하여 실제 Gradient를 효율적으로 계산하는 방법으로, PyTorch의 `autograd`와 Neural Network의 Backpropagation에 사용된다.**

# 2. Gradient Descent

Gradient Descent의 기본 Update Rule은 다음과 같다.

$$
\mathbf{w}_{t+1} = \mathbf{w}_t - \eta \nabla_{\mathbf{w}} L(\mathbf{w}_t)
$$

여기서

- $\mathbf{w}_t$ : 현재 Parameter
- $\mathbf{w}_{t+1}$ : Update 이후 Parameter
- $\eta$ : Learning Rate
- $\nabla L$ : 현재 위치의 Gradient

이다.

전체 흐름은

```text
현재 Parameter
      ↓
Prediction
      ↓
Loss 계산
      ↓
Gradient 계산
      ↓
Gradient의 반대 방향으로 이동
      ↓
새 Parameter
```

이다.

이 과정을 반복하면서 Loss를 줄여간다.

---

# 3. 왜 Gradient 앞에 마이너스가 붙는가?

Gradient는 함수가 가장 빠르게 **증가하는 방향**을 나타낸다.

따라서

$$
+\nabla L
$$

방향으로 이동하면 Loss가 증가한다.

우리는 Loss를 최소화해야 하므로 반대 방향인

$$
-\nabla L
$$

로 이동해야 한다.

즉

$$
\mathbf{w}_{new} = \mathbf{w}_{old} - \eta\nabla L
$$

에서 `-`는 **Loss가 감소하는 방향으로 이동한다는 의미**이다.

---

# 4. Step Size와 Learning Rate

Gradient Descent에서 $\eta$는 일반적으로 **Learning Rate**라고 부른다.

기본적인 Gradient Descent 문맥에서는 Step Size라고도 표현한다.

```text
Learning Rate
≈ Step Size를 결정하는 계수
```

즉

$$
\eta
$$

가 클수록 한 번의 Update에서 더 크게 움직이고, 작을수록 더 조금 움직인다.

다만 엄밀하게 실제 Parameter 이동량은

$$
\Delta\mathbf{w} = -\eta\nabla L
$$

이므로 Gradient의 크기에도 영향을 받는다.

따라서 기본적인 GD에서는

> **Learning Rate를 Step Size라고 이해해도 되지만, 실제 이동 거리 자체와 완전히 같은 값은 아니다.**

또한 Adam과 같은 Adaptive Optimizer에서는 Parameter마다 실제 적용되는 Effective Step Size가 달라질 수 있다.

---

# 5. Learning Rate가 너무 크다면

Learning Rate가 지나치게 크면 최적점을 지나쳐 버릴 수 있다.

이를 **Overshooting**이라고 한다.

```text
Loss

     ●
    / \
   /   \
 ●       ●
      ↓
Minimum
```

Parameter가 Minimum을 중심으로 계속 크게 왔다 갔다 하거나 더 멀어질 수 있다.

```text
Learning Rate 너무 큼
       ↓
Overshooting
       ↓
Loss 진동
       ↓
Divergence 가능
```

심한 경우 Loss가 계속 증가하거나 `NaN`이 발생할 수도 있다.

---

# 6. Learning Rate가 너무 작다면

Learning Rate가 너무 작으면 한 번의 Parameter Update가 매우 작아진다.

```text
Learning Rate ↓
       ↓
Update 크기 ↓
       ↓
Training Time ↑
```

즉 최적점으로 향하고 있더라도 매우 많은 Iteration이 필요할 수 있다.

또한 Plateau처럼 Gradient가 매우 작은 영역에서는 학습이 거의 진행되지 않는 것처럼 보일 수 있다.

다만 **Learning Rate가 작다고 해서 그 자체로 Local Minimum에 더 쉽게 빠진다고 단정하는 것은 적절하지 않다.**

핵심 문제는 주로

```text
Convergence가 지나치게 느려짐
```

이다.

---

# 7. 적절한 Learning Rate

이상적인 Learning Rate는

```text
너무 크지도 않고
너무 작지도 않은 값
```

이다.

개념적으로

```text
너무 큼
→ 발산 가능

적절함
→ 빠르고 안정적으로 수렴

너무 작음
→ 학습이 지나치게 느림
```

이라는 관계가 있다.

그래서 Learning Rate는 Deep Learning에서 매우 중요한 **Hyperparameter**이다.

---

# 8. Learning Rate Scheduler

Training 과정 전체에서 같은 Learning Rate를 사용할 필요는 없다.

초기에는 비교적 큰 Learning Rate로 빠르게 이동하고, Training이 진행될수록 Learning Rate를 줄일 수 있다.

```text
Training 초기
Learning Rate 크게
      ↓
빠른 이동

Training 후반
Learning Rate 작게
      ↓
세밀한 조정
```

이를 **Learning Rate Scheduling**이라고 한다.

대표적으로

```text
Step Decay
Exponential Decay
Cosine Annealing
```

등이 있다.

---

# 9. Gradient Descent는 어떤 데이터를 이용해 Gradient를 계산하는가?

Gradient를 계산하려면 Training Data가 필요하다.

이때 한 번의 Parameter Update에 몇 개의 Sample을 사용하는가에 따라 크게 세 가지 방식으로 구분할 수 있다.

```text
Batch Gradient Descent
Stochastic Gradient Descent
Mini-batch Gradient Descent
```

---

# 10. Batch Gradient Descent

Batch Gradient Descent는 **전체 Training Dataset**을 이용하여 한 번의 Gradient를 계산한다.

```text
전체 Training Data
        ↓
Gradient 계산
        ↓
Parameter Update 1회
```

예를 들어 Training Sample이 10,000개라면 10,000개의 Sample을 모두 이용한 뒤 Parameter를 한 번 Update한다.

### 장점

전체 Dataset을 이용하므로 Gradient가 비교적 안정적이다.

```text
Update Direction
→ 안정적
```

### 단점

Dataset이 커지면

```text
Memory 사용량 ↑
연산량 ↑
Update당 시간 ↑
```

이 된다.

---

# 11. Stochastic Gradient Descent

Stochastic Gradient Descent에서는 **Sample 하나**를 이용하여 Gradient를 계산하고 바로 Parameter를 Update한다.

```text
Sample 1
 ↓
Update

Sample 2
 ↓
Update

Sample 3
 ↓
Update
```

따라서 Parameter Update가 매우 자주 발생한다.

장점은 빠르게 Update할 수 있고, Gradient에 Noise가 존재하여 복잡한 Loss Landscape에서 탐색에 도움이 될 수 있다는 것이다.

하지만

```text
Gradient Variance ↑
      ↓
Update가 크게 흔들림
```

이라는 특징이 있다.

최적점 부근에서도 Parameter가 계속 흔들릴 수 있다.

---

# 12. Mini-batch Gradient Descent

Mini-batch Gradient Descent는 Batch GD와 SGD의 중간 방식이다.

전체 Dataset 중 일부 Sample을 하나의 Batch로 묶는다.

예를 들어

```text
Batch Size = 32
```

라면 32개의 Sample을 이용하여 Gradient를 계산한 뒤 Parameter를 한 번 Update한다.

```text
32 Samples
    ↓
Gradient
    ↓
1 Update
```

현재 Deep Learning에서는 이 방식이 가장 일반적으로 사용된다.

---

# 13. Batch Size

Mini-batch에 포함되는 Sample 수를 **Batch Size**라고 한다.

대표적으로

```text
8
16
32
64
128
```

등을 사용할 수 있다.

Deep Learning 코드에서 흔히

```python
batch_size = 32
```

라고 표현하지만 Gradient Descent의 엄밀한 분류 관점에서는 이는 **Mini-batch Size**이다.

실무에서는 문맥상 그냥 Batch라고 부르는 경우가 많다.

---

# 14. 세 가지 Gradient Descent 비교

| 구분 | Batch GD | SGD | Mini-batch GD |
| --- | --- | --- | --- |
| Update에 사용하는 Data | 전체 Dataset | 1 Sample | 일부 Sample |
| Gradient 안정성 | 높음 | 낮음 | 중간 |
| Update 빈도 | 낮음 | 매우 높음 | 높음 |
| GPU 병렬 처리 | Dataset 크기에 따라 부담 | 비효율적 | 효율적 |
| Memory 요구량 | 큼 | 작음 | 조절 가능 |
| 딥러닝 활용 | 제한적 | 일부 | 가장 일반적 |

Mini-batch는

```text
SGD의 빠른 Update
+
Batch GD의 안정성
+
GPU Parallel Processing
```

사이에서 좋은 균형을 제공한다.

---

# 15. Loss Function

Gradient Descent를 사용하려면 먼저 무엇을 최소화할 것인지 정의해야 한다.

이를 **Loss Function**이라고 한다.

```text
Prediction
    ↓
Loss Function
    ↑
Target
```

Loss는 Model의 Prediction과 실제 Target이 얼마나 다른지 나타낸다.

---

# 16. Linear Regression

Linear Regression은 연속적인 값을 예측하는 대표적인 Regression Model이다.

기본 Model은

$$
\hat{y} = \mathbf{w}^T\mathbf{x}+b
$$

로 표현할 수 있다.

예를 들어

```text
집의 크기
     ↓
Linear Regression
     ↓
집 가격
```

처럼 연속적인 수치를 예측한다.

---

# 17. Linear Regression의 MSE

Linear Regression에서는 대표적으로 **Mean Squared Error(MSE)** 계열 Loss를 사용한다.

일반적인 MSE는

$$
MSE = \frac{1}{m} \sum_{i=1}^{m} (y_i-\hat{y}_i)^2
$$

이다.

수학적 유도를 편하게 하기 위해 다음처럼 $\frac12$을 추가한 형태도 자주 사용한다.

$$
L = \frac{1}{2m} \sum_{i=1}^{m} (y_i-\hat{y}_i)^2
$$

---

# 18. 왜 2로 나누는가?

이 $\frac12$의 가장 큰 목적은 **미분을 깔끔하게 만들기 위해서**이다.

간단한 함수

$$
L=\frac12(y-\hat{y})^2
$$

를 생각해보자.

$\hat{y}$에 대해 미분하면

$$
\frac{\partial L}{\partial\hat{y}} = \frac12 \cdot 2(\hat{y}-y)
$$

가 되어

$$
\frac{\partial L}{\partial\hat{y}} = \hat{y}-y
$$

가 된다.

즉 제곱을 미분할 때 나오는 `2`와 앞의 $\frac12$가 서로 상쇄된다.

```text
Square 미분
→ 2가 앞으로 나옴

1/2
→ 2와 약분

결과
→ 수식이 단순해짐
```

---

# 19. 1/2을 넣어도 최적점이 같은 이유

Loss에 양의 상수를 곱해도 Loss를 최소화하는 Parameter의 위치는 변하지 않는다.

예를 들어

$$
L_1=(y-\hat{y})^2
$$

와

$$
L_2=\frac12(y-\hat{y})^2
$$

는 값의 크기는 다르지만 Minimum이 발생하는 위치는 동일하다.

따라서 $\frac12$은 주로 **미분 계산을 편하게 하기 위한 수학적 관례**이다.

엄밀하게 말하면

$$
\frac{1}{2m}\sum(...)
$$

은 일반적으로 정의되는 MSE의 절반이지만, Optimization의 최적해는 동일하다.

---

# 20. Vector 형태의 Linear Regression

Training Sample 전체를 Matrix로 표현하면 Linear Regression은

$$
\hat{\mathbf{y}} = X\mathbf{w}
$$

로 표현할 수 있다.

Loss를

$$
L = \frac{1}{2m} \left\| \mathbf{y}-X\mathbf{w} \right\|_2^2
$$

라고 하자.

Gradient는

$$
\nabla_{\mathbf{w}}L = \frac{1}{m} X^T (X\mathbf{w}-\mathbf{y})
$$

가 된다.

여기서

```text
Xw - y
```

는 Prediction과 Target 사이의 Error Vector이고,

```text
Xᵀ(Xw-y)
```

는 각 Feature가 Error에 얼마나 기여하는지를 Parameter별로 모은 Gradient라고 볼 수 있다.

---

# 21. Linear Regression에 Gradient Descent 적용

Gradient를 계산했으므로 Weight Update는

$$
\mathbf{w}_{t+1} = \mathbf{w}_t - \eta \frac{1}{m} X^T (X\mathbf{w}_t-\mathbf{y})
$$

가 된다.

즉

```text
Prediction
    ↓
Error
    ↓
Gradient
    ↓
Learning Rate 적용
    ↓
Weight Update
```

의 구조이다.

---

# 22. Logistic Regression

Logistic Regression은 이름에 `Regression`이 들어가지만 대표적인 **Classification Model**이다.

Binary Classification을 예로 들면 먼저 Linear Score를 계산한다.

$$
z = \mathbf{w}^T\mathbf{x}+b
$$

그리고 이를 Sigmoid Function에 입력한다.

$$
\sigma(z) = \frac{1}{1+e^{-z}}
$$

Sigmoid의 출력 범위는

$$
0<\sigma(z)<1
$$

이므로 Class Probability로 해석할 수 있다.

---

# 23. Logistic Regression의 Prediction

예를 들어

$$
P(y=1|x)=0.9
$$

가 나오면 Model은 Class 1일 가능성을 높게 본다는 의미이다.

일반적인 Binary Classification에서는 Threshold를 이용하여 최종 Class를 결정할 수 있다.

```text
Probability ≥ 0.5
→ Class 1

Probability < 0.5
→ Class 0
```

---

# 24. Logistic Regression도 Linear Model이다

Sigmoid가 Non-linear Function이기 때문에 Logistic Regression 자체도 복잡한 Non-linear Decision Boundary를 만든다고 생각하기 쉽다.

하지만 기본 Logistic Regression의 Decision Boundary는

$$
\mathbf{w}^T\mathbf{x}+b=0
$$

이다.

왜냐하면 Binary Classification에서

$$
\sigma(z)=0.5
$$

가 되는 지점은

$$
z=0
$$

이기 때문이다.

따라서 기본 Logistic Regression은 **원래 Feature Space에서 Linear Decision Boundary를 가지는 Classifier**이다.

---

# 25. Logistic Regression의 Loss

Binary Logistic Regression에서는 일반적으로 **Binary Cross Entropy(BCE)** 또는 Log Loss를 사용한다.

$$
L = - [ y\log(p) + (1-y)\log(1-p) ]
$$

여기서

- $y$ : 실제 Class
- $p$ : Class 1일 Prediction Probability

이다.

Model이 실제 정답에 높은 Probability를 줄수록 Loss는 작아진다.

---

# 26. Linear Regression과 Logistic Regression 비교

| 구분 | Linear Regression | Logistic Regression |
| --- | --- | --- |
| 목적 | Regression | Classification |
| Target | 연속적인 수치 | Class |
| Linear Score | $w^Tx+b$ | $w^Tx+b$ |
| 최종 Output | 실수 | Probability |
| Output Function | Identity | Sigmoid |
| 대표 Loss | MSE | Binary Cross Entropy |
| Decision Boundary | 해당 없음 | Linear |

두 Model 모두 먼저

$$
z=\mathbf{w}^T\mathbf{x}+b
$$

라는 Linear Combination을 사용한다.

차이는 그 이후이다.

```text
Linear Regression

z
↓
그대로 Output
↓
Continuous Value
```
```text
Logistic Regression

z
↓
Sigmoid
↓
Probability
↓
Class
```

---

# 27. Multi-class Logistic Regression

Class가 2개보다 많은 경우에는 Logistic Regression을 Multi-class Classification으로 확장할 수 있다.

대표적으로 **Softmax Regression**을 사용할 수 있다.

각 Class에 대한 Score를

$$
z_1,z_2,\dots,z_K
$$

라고 하면 Softmax는

$$
P(y=k) = \frac{e^{z_k}} {\sum_{j=1}^{K}e^{z_j}}
$$

로 각 Class의 Probability를 계산한다.

전체 Probability의 합은

$$
\sum_{k=1}^{K}P(y=k)=1
$$

이다.

---

# 28. Perceptron과의 연결

Perceptron 역시

$$
z = \mathbf{w}^T\mathbf{x}+b
$$

라는 Linear Score를 이용한다.

다만 Classical Perceptron은 Step Function을 사용하여 Class를 바로 결정한다.

```text
Perceptron

Linear Score
     ↓
Step
     ↓
Class
```

Logistic Regression은

```text
Linear Score
     ↓
Sigmoid
     ↓
Probability
     ↓
Class
```

이다.

여기서 중요한 차이는 Classical Perceptron의 Step Function을 통한 학습은 일반적인 미분 기반 Backpropagation으로 수행되지 않는다는 것이다.

Logistic Regression은 Sigmoid와 Differentiable Loss를 이용해 Gradient-based Optimization을 적용할 수 있다.

---

# 29. 전체 개념 연결

지금까지의 개념을 하나로 연결하면 다음과 같다.

```text
Training Data
      ↓
Model
      ↓
Prediction
      ↓
Loss Function
      ↓
Gradient
      ↓
Gradient Descent
      ↓
Learning Rate
      ↓
Parameter Update
      ↓
다시 Prediction
```

Linear Regression에서는

```text
Model
→ Linear

Loss
→ MSE
```

이고,

Logistic Regression에서는

```text
Model
→ Linear + Sigmoid

Loss
→ Cross Entropy
```

이다.

하지만 두 경우 모두 궁극적인 목표는

$$
\mathbf{w}^* \in \arg\min_{\mathbf{w}} L(\mathbf{w})
$$

즉 **Loss를 최소화하는 Parameter를 찾는 것**이다.

# 30. Gradient Descent와 Optimizer

Gradient Descent는 현대 Optimizer들의 기본이 되는 개념이다.

기본 Gradient Descent는

$$
\mathbf{w}_{t+1} = \mathbf{w}_t - \eta\nabla L
$$

이지만 실제 Deep Learning에서는 이를 개선한

```text
SGD
Momentum
AdaGrad
RMSProp
Adam
AdamW
```

등의 Optimizer가 널리 사용된다.

이들은 모두 결국

> **Gradient 정보를 이용하여 Parameter를 어떤 방식으로 Update할 것인가**

를 다르게 설계한 방법이다.

---

# 핵심 정리

| 개념 | 핵심 |
| --- | --- |
| Loss Function | Model의 Prediction Error를 수치화 |
| Gradient | Loss가 가장 빠르게 증가하는 방향 |
| Gradient Descent | Gradient 반대 방향으로 Parameter Update |
| Learning Rate | Update 크기를 조절하는 Hyperparameter |
| Step Size | 기본 GD에서는 Learning Rate와 밀접하게 사용되는 표현 |
| Batch GD | 전체 Dataset으로 Gradient 계산 |
| SGD | Sample 1개로 Gradient 계산 |
| Mini-batch GD | 일부 Sample로 Gradient 계산 |
| MSE의 $\frac12$ | 미분 시 계수 2를 상쇄하기 위한 편의 |
| Linear Regression | 연속적인 값을 예측 |
| Logistic Regression | Class Probability를 이용한 분류 |
| Sigmoid | Linear Score를 0~1 Probability로 변환 |
| BCE | Binary Logistic Regression의 대표적인 Loss |

# 한 문장으로 정리

Gradient Descent는 **Loss Function의 Gradient 반대 방향으로 Learning Rate만큼 Parameter를 반복적으로 갱신하여 최적의 Parameter를 찾는 기본 Optimization 방법이며, Linear Regression과 Logistic Regression 역시 서로 다른 Output과 Loss를 사용하지만 이러한 Gradient-based Learning의 동일한 틀 안에서 이해할 수 있다.**
